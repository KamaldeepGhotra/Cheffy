# Cheffy — Meal Plan (Workstream 3)

**Owner:** Andreas. **Branch:** `feature/meal-plan`, stacked on `feature/inventory-ux` (PR #1).

**Goal:** Spec flow 4 — assign recipes to days and to a person for a week, and generate that week's grocery list from the plan. The spec left this deliberately manual (no rotation or optimization logic), and this plan keeps it that way.

## Decisions

- **A plan is just the set of entries for one (household, Monday-start week).** No separate `MealPlan` parent row — the spec sketched one, but it had no fields of its own beyond `week_start_date`, so entries carry `week_start` directly. Add a parent row later if a week ever needs its own metadata (a name, a "shopped" flag).
- **Seven days, no meal slots.** Each entry has `day` 0–6 (Mon–Sun). Breakfast/lunch/dinner slots were considered and rejected as more clicks than the "prep a few days, split them" workflow needs. Adding a `slot` column later is additive.
- **Members are hardcoded** to `Andreas` and `Kam` in the frontend. The backend accepts any `assigned_to` string. When Supabase auth lands, the member list comes from the two user accounts and `assigned_to` becomes a user id.
- **Grocery list from the plan reuses the existing endpoint.** The page sums `servings` per recipe across the week's entries and calls `POST /grocery-list` with that map. No change to the grocery router, which Workstream 1 owns.
- **`GET /recipes` added minimally.** The picker needs a recipe list, which is Workstream 1's Task 4. To avoid blocking, this branch adds `GET /recipes` returning `list[RecipeOut]`, newest first, accepting (and ignoring) `household_id` so the frontend call signature matches Task 4's planned `listRecipes(householdId)`. **Kam: Task 4 becomes "add `match_percentage` and sort by it" on top of this function rather than writing it from scratch.**

## Known gaps

- **"Servings" multiplies the whole recipe.** Gemini returns quantities for a full recipe (usually ~4 servings), and the existing grocery math does `quantity × servings`, so "2 servings" of spaghetti asks for 1600 g of tomatoes. This is the grocery router's existing behaviour, not new here, but the meal plan makes it visible. Fix belongs with the recipe/Gemini work: either ask Gemini for `servings_per_recipe` and divide, or rename the field to "batches".
- Entries don't reserve inventory and cooking doesn't subtract it. Separate feature.
- No edit; remove and re-add.
